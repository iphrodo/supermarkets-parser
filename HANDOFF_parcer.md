# Handoff: Nuxt-агрегатор акцій Lidl BG + Kaufland BG (Варна)

Контекст для Claude Code у VS Code. Це продовження розвідки, яку почав Claude у чаті (claude.ai). Веб-версія мала обмежені мережеві інструменти (allowlist доменів для bash, немає підключеного браузера з DevTools), тому частину розвідки не вдалося завершити. У VS Code цих обмежень немає — є повний доступ до інтернету з машини користувача.

---

## 1. Загальна задача

Побудувати full-stack застосунок на **Nuxt 3 (SSR) + TypeScript**, задеплойний на **Vercel**, який:
- парсить щотижневі акції продуктових мереж **Lidl Bulgaria** (`lidl.bg`) та **Kaufland Bulgaria** (`kaufland.bg`);
- показує їх на одній сторінці з фільтрами (мережа, категорія, ціна);
- орієнтований на користувача у **Варні, Болгарії**.

Стек: Nuxt 3, React ні — саме Vue 3 + Nuxt, TypeScript, Tailwind, Vitest, Storybook (той самий стек, що на робочому SF Next проєкті користувача). Парсинг — легкі HTTP-клієнти (`ofetch`/`cheerio`) у `server/api/*`, без Puppeteer/Playwright у продакшн-рантаймі Vercel (можна використовувати Playwright лише як **офлайн інструмент розвідки**, не як частину деплою).

Користувач — Микола (Mykola), фронтенд-розробник ~10 років, SFCC/SFRA бекграунд, зараз освоює fullstack (React/TS на роботі, тут — Vue/Nuxt для практики). Живе у Варні. Проєкт особистий, некомерційний.

## 2. Статус: що вже перевірено (Фаза 1, зроблено в чаті)

### 2.1 Kaufland BG — джерело є, робоче

`https://www.kaufland.bg/aktualni-predlozheniya/oferti.html` — **повністю server-side rendered HTML**, жодного JS не треба. Підтверджено прямим `web_fetch` — витягнуто ~600 реальних позицій без жодного API-виклику.

У розмітці присутні:
- бренд + назва товару (окремо)
- фасовка (`3 л/ 1455 г`, `кг`, `0,7 л`)
- знижка % (`-66%`)
- ціна в EUR і в BGN одночасно (`5,10 €` / `9,97 ЛВ.`)
- стара ціна (не завжди присутня)
- тип лояльності: звичайна ціна / `Цена с KAUFLAND CARD XTRA` / `-30% отстъпка с KAUFLAND CARD` / `специална цена с KAUFLAND CARD XTRA` — це **різні механіки**, не один булевий прапорець
- механіки типу `КУПИ 1+1 ПОДАРЪК`, `КУПИ 2+1 ПОДАРЪК`
- ліміти купівлі (`до 5 кг на покупка`)
- категорія — з заголовків блоків (Плодове и зеленчуци, Месо и колбаси, Млечни продукти, і т.д.)
- дати валідності — **per-блок**, не глобальні (основний тиждень 27.07–02.08, окремо "Супер уикенд" 29.07–01.08, окремо "Цветя" 28.07–02.08)

Категорійний фільтр — query param `?kloffer-category=...` (значення закодовані в URL кілька разів, брідко, але робоче).

Проспекти (PDF/leaflet viewer) лежать на окремому домені:
```
https://leaflets.kaufland.com/bg-BG/BG_bg_{type}_{storeId}_BG{week}-{code}/ar/{storeId}
```
Store ID сидить прямо в URL (за замовчуванням віддало `3100` — Пернік).

### 2.2 Lidl BG — джерело складніше, JS-рендерене

Перевірено `https://www.lidl.bg/c/aktsiya/a10099116`. У SSR HTML є заголовки кампаній, але тіла товарів під ними порожні — довантажуються клієнтським JS. Класичний `cheerio` по цих сторінках нічого не витягне.

Lidl Plus (окремі промо, купони) — за логіном у мобільному застосунку, поза межами проєкту.

Операційна деталь для розкладу крону: у Lidl викладка **двічі-тричі на тиждень** (пн, чт, іноді сб), не раз як у Kaufland.

### 2.3 Юридична межа (важливо, не обходимо)

- **Категорично не робимо**: обхід Cloudflare/anti-bot, підбір заголовків спеціально під обхід, CAPTCHA-байпас, емуляція "readers з Варни" через підроблені cookies.
- Агрегатори (broshura.bg, kimbino.bg, ebroshura.bg) технічно легші, але юридично гірше — у них прямий комерційний інтерес саме в цих даних, у ToS зазвичай прямо забороняють автоматичний збір. **Виключити з розгляду.**
- Прийнятний профіль навантаження для особистого некомерційного проєкту: 1–2 запити на добу на кожен сайт (крон), атрибуція джерела в UI, ніякої монетизації чи публічного трафіку понад особисте використання.

### 2.4 Vercel + кешування — виправлений план

`cachedEventHandler` / `useStorage()` з дефолтним `memory` драйвером **не переживає холодні старти на serverless**.

**Рекомендація:** cron раз на добу пише знапшот у зовнішній KV (Vercel KV / Upstash Redis), сторінка читається через ISR (`routeRules`).

**Пам'ятки Vercel Hobby:** cron максимум раз на добу; час спрацювання гарантований лише в межах години; тільки UTC; дефолтний таймаут функції — 10 с.

### 2.5 Валюта — критично й терміново

Болгарія перейшла на євро **1 січня 2026**, євро — єдиний законний засіб платежу з **1 лютого 2026**. Подвійне позначення цін (лев + євро) юридично обов'язкове **до 8 червня 2026**. Обидва сайти зараз (кінець липня 2026) показують обидві валюти.
- Схема з єдиним полем `price: number, currency: "BGN"` — вже неправильна сьогодні.
- `priceBgn` має бути nullable з самого початку (зникне після 08.06.2026).

## 4. Фаза 2 — довершення розвідки (ЗРОБЛЕНО у VS Code, 2026-08-01)

### 4.1 robots.txt — ПЕРЕВІРЕНО

**lidl.bg:**
```
User-agent: *
Disallow: /q/search?id=*
Disallow: /cc.js*
Disallow: /1* /2* /3* /4* /5* /6* /7* /8* /9*   (нумеричні шляхи верхнього рівня)
Disallow: /cdn/assets/cwv/
Sitemap: https://www.lidl.bg/static/sitemap.xml
```
Кампанійні сторінки (`/c/aktsiya/...`) і шлях до XLSX (`/explore/...`) **не заблоковані** — обидва починаються не з цифри.

**kaufland.bg:**
```
User-agent: *
Disallow: /etc.clientlibs/
Allow: /etc.clientlibs/kaufland
Sitemap: https://www.kaufland.bg/.sitemap.xml
```
`/aktualni-predlozheniya/oferti.html` не заблокований.

Висновок: обидва джерела юридично/технічно чисті для нашого профілю навантаження.

### 4.2 Lidl XLSX — ЗАВАНТАЖЕНО Й ПРОАНАЛІЗОВАНО. Це змінює архітектуру парсера Lidl.

Обидва файли завантажились без проблем (`curl`, без будь-якого спеціального User-Agent-байпасу):
- `ExportFirstList.xlsx` — 100 080 рядків, схема: Код, Търговски обект (магазин), Наименование на продукта, Код на продукта, Категория, Цена, Цена в промоция.
- `ExportSecondList.xlsx` — 100 081 рядок, **набагато багатша схема**, це офіційний ЗУПА-звіт (моніторинг цін під час переходу на євро):
  ```
  EKATTE на населено място | Данни за търговския обект | Име на продукта | Марка |
  Нетно количество | Категория | Код на продукта |
  Референтната цена / цена на дребно | Текущата намалена цена |
  Срок на намаление от | Срок на намаление до | Процентното изменение
  ```
  Приклад рядка з активною знижкою:
  ```
  Железница Кашкавал от краве мляко | ref 9.71 | cur 7.75 |
  from 2026-07-06 | until 2026-08-02 | -20.19%
  ```

**Це найкраще джерело для Lidl-парсера, значно краще за передбачений у Фазі 1 сценарій з Playwright:**
- 695 унікальних кодів товару, ~143 магазини.
- Офіційний, юридично обов'язковий файл (не потребує обходу JS-рендерингу чи anti-bot).
- Містить усе, чого бракувало в початковій схемі: originalPrice, discountedPrice, validFrom, validUntil, percentage — без ручного рахування знижки.
- 3520 з 100 081 рядків мають активну знижку (реальні акційні позиції).

**Playwright-розвідка (розділ 4.2 старого плану) виявилась НЕПОТРІБНОЮ.** XLSX повністю закриває потребу в даних Lidl без жодного клієнтського JS чи ризику анти-бота. Рекомендація: викреслити з плану пошук внутрішнього API Schwarz retcat — XLSX простіший, стабільніший і офіційний.

### 4.3 Store-специфічність цін — ВІДПОВІДЬ ОТРИМАНО (для Lidl), для Kaufland неоднозначно

**Lidl: ціни НЕ відрізняються між магазинами.** Перевірено програмно: для 695 унікальних кодів товару (List1) і 695 кодів (List2) з ~143 магазинами кожен — **0 випадків реальної варіації ціни** (`Референтна ціна` та `Текуща намалена ціна` ідентичні у всіх магазинах для одного коду товару; "варіації", знайдені первинним скриптом, виявились лише присутністю/відсутністю знижки в конкретному магазині, не різницею в самій ціні).

Це відповідає на відкрите питання №1 з розділу 5 старого плану: **ціни національні, лише асортимент/наявність відрізняється по магазинах.** Схема може прибрати `storeId`/`storeName` з offer-запису і залишити тільки `scope: 'national'` — для Lidl це підтверджено фактом, не припущенням.

**Kaufland: не вдалося перевірити без headless-браузера.** Сторінка `/moyat-kaufland/uslugi/filiali.html` (список магазинів) сама є SPA без даних у SSR HTML — store ID не витягнути через curl. Враховуючи підтверджений факт для Lidl (та типову практику національних промо-кампаній у рітейлі), розумний дефолт — вважати Kaufland теж національним (`scope: 'national'`), поки не з'явиться конкретна причина сумніватися. Якщо знадобиться остаточна перевірка — потрібен Playwright з перехопленням XHR на сторінці вибору магазину.

### 4.4 Товарні посилання Kaufland — ВІДПОВІДЬ: посилань НЕМАЄ, але є краща альтернатива для ID

Завантажено `oferti.html` (5.2 МБ SSR HTML) і перевірено сирий DOM (не через markdown-екстрактор, а напряму):
- Усі 1190 карток товару мають `<a class="k-product-tile" href="#" tabindex="0">` — **href завжди `"#"`, реального посилання на товарну сторінку немає взагалі.**
- Висновок: `productUrl` треба **прибрати зі схеми Kaufland-офера повністю** (не nullable-поле, а відсутнє поле) — воно не існує на цьому джерелі.

**Знахідка-компенсація:** URL зображення містить стабільний EAN/GTIN-подібний код товару:
```
https://kaufland.media.schwarz/is/image/schwarz/8606018614950_BG_P
```
`8606018614950` виглядає як справжній EAN-13 штрихкод. Це набагато надійніший кандидат на `productKey` для Kaufland, ніж (назва + фасовка), яка, як з'ясовано в чаті, дублюється і має нестабільний порядок токенів. Сам URL зображення лишається недовговічним (може проксуватись/змінюватись), але штрихкод у його складі варто парсити як окреме поле `ean: string | null`.

Приклад повної картки (для довідки по структурі DOM):
```html
<a class="k-product-tile" href="#" tabindex="0">
  <img class="k-product-tile__main-image" src=".../8606018614950_BG_P" alt="Изображение на ALOMA Сладолед XXL...">
  <div class="k-product-tile__title">ALOMA</div>
  <div class="k-product-tile__subtitle">Сладолед XXL различни вкусове</div>
  <div class="k-product-tile__unit-price">3 л/ 1455 г</div>
  <div class="k-price-tag__discount">-66%</div>
  <div class="k-price-tag__price">5,10 € </div>
  <div class="k-price-tag__old-price">15,33 €</div>
  <!-- друга price-tag для BGN -->
  <div class="k-price-tag__price">9,97 ЛВ. </div>
  <div class="k-price-tag__old-price">29,98 ЛВ.</div>
</a>
```

## 5. Відкриті питання — ОНОВЛЕНО після Фази 2

1. ~~Ціни відрізняються по магазинах, чи тільки асортимент?~~ **Закрито для Lidl: тільки асортимент, ціни національні.** Для Kaufland — не перевірено технічно, дефолт `national` до появи конкретної підстави сумніватися.
2. ~~Що реально всередині Lidl XLSX?~~ **Закрито: офіційний ЗУПА price-monitoring файл із готовими originalPrice/discountedPrice/validFrom/validUntil/percentage. Playwright для Lidl більше не потрібен.**
3. **Яка справжня мета проєкту?** ("Що дешеве цього тижня" vs "Історія цін з часом") — досі відкрите, продуктове рішення, не технічне.
4. **Vercel Hobby чи Pro?** досі відкрите — визначає, чи можливий крон частіше за раз на добу.

## 7. Що категорично не робити (незалежно від фази)

- Не обходити anti-bot/Cloudflare захист, не підбирати заголовки спеціально під обхід.
- Не емулювати чужу сесію/локацію підробленими cookies.
- Не парсити агрегатори (broshura.bg, kimbino.bg тощо) — юридично гірше за прямі сайти мереж.
- Не публікувати/монетизувати результат без окремого юридичного аналізу — проєкт вважається особистим некомерційним.
